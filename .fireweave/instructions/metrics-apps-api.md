## How to emit a metric — `apps/api` (ts-server)

**This app's FireWeave files:** control points `apps/api/src/fireweave/control-points.ts`; start `apps/api/src/fireweave/start.ts`, imported first by `apps/api/src/app.ts`; stamps `.fireweave/stamps.ts`.

**Client:** `otel-sdk`

**Import, as it appears in this repo:** `import { startTelemetry, type Telemetry } from "@keel/otel";`

**Counter:** `requests.add(1, attributes) / business[signal.business].add(1, attributes) for "keel.card.created" | "keel.card.moved" | "keel.comment.created" | "keel.card.starred"`

**Histogram / timing:** `duration.record(signal.durationMs, attributes) as "http.server.request.duration" (unit: ms)`

**Where the instrument comes from:** apps/api never calls the OTel API directly: createApp() wraps every route with observe(telemetry) (apps/api/src/observe.ts), and that middleware calls telemetry.record(signal) once per request, where telemetry = startTelemetry() from @keel/otel (packages/otel/src/index.ts). The counters/histogram are created once inside startTelemetry() and only incremented through record().

**Wrapper to prefer over the raw client:** telemetry.record(signal) in apps/api/src/observe.ts — a route handler reports a business event by calling c.set("keelBusiness", <BusinessMetric>) (see apps/api/src/routes/cards.ts) before returning; the observe() middleware then forwards it to @keel/otel's startTelemetry(), which only increments the matching counter when the response status also matches (e.g. "keel.card.created" + 201). Every metric name must already exist in packages/catalog/metrics.yaml or startTelemetry() throws at startup.

**Tag / label convention (including the cohort key):** OTel attributes set in packages/otel/src/index.ts signalAttributes(): http.route, http.request.method, http.response.status_code, plus optional keel.run_id, keel.actor, keel.journey, keel.step, keel.pace forwarded from the x-keel-* request headers.

**Real examples from this repo:**

- `apps/api/src/observe.ts:30`

